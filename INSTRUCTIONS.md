# Financial Fraud Detection Engine — Agent Instructions

## Mission
Continue developing the project autonomously until the current milestone is complete.

## Working rules
1. Inspect the existing code before modifying it.
2. Never rewrite a whole file when a targeted change is sufficient.
3. Make changes in small, testable steps.
4. After every significant change, run the relevant tests or evaluation scripts.
5. If a test fails, diagnose and fix the problem before moving forward.
6. Preserve working functionality.
7. Do not delete working code just to simplify implementation.
8. Create a checkpoint/commit after completing a meaningful milestone.
9. Continue from the last successful checkpoint after an error.
10. Do not stop merely because one implementation attempt fails.
11. Avoid asking for confirmation for routine coding, testing, debugging, and file operations.
12. Ask for confirmation only for destructive operations or genuinely ambiguous architectural decisions.

## Project priorities
- Correctness
- Reproducibility
- Testability
- Maintainability
- Real-time performance
- Fraud-detection evaluation quality

## Before declaring completion
Verify that:
- Backend starts successfully.
- All important tests pass.
- Model/evaluation pipeline runs.
- Data generation works.
- Graph/anomaly detection works.
- Fraud scoring works.
- API works.
- Frontend works if applicable.
- Existing functionality has not been broken.
